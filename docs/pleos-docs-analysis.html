Pleos 개발 문서 분석

document.pleos.ai의 사이트맵에서 API 레퍼런스를 제외한 가이드 문서 153쪽(개발자 가이드 139쪽 + Connect Mobile 14쪽)을 모두 받아 읽었습니다. API 레퍼런스는 필요한 클래스만 SDK 바이너리에서 직접 확인했습니다. 각 내용이 동승자 멀미 저감 앱에 어떤 의미인지를 기준으로 정리했습니다.

작성 2026-11-08기준: Emulator v2.1.0 · Vehicle 2.3.2 · NaviHelper 3.0.5 · TTS/STT 3.3.1 · FusedLocation 1.1.3
핵심 요약

문서를 끝까지 읽고 나니 기획에 유리한 사실 셋, 반드시 설계에 반영해야 할 제약 셋이 나왔습니다.

  • 기회 내비가 "다음 회전까지 남은 거리"를 줍니다. NaviHelper onTBTInfo()로 회전 종류와 거리를, onCautionPointInfo()로 과속방지턱·내리막 구간까지 거리를 받습니다. 차속으로 나누면 "3초 뒤 우회전"을 계산할 수 있어 기획서의 2~4초 예측이 성립합니다.
  • 기회 차속은 표준 Car API가 공식 경로입니다. Pleos는 속도·기어 같은 표준 데이터를 AAOS Car API로 읽으라고 명시하고, Vehicle SDK 2.3.2에서 자체 속도 리스너를 아예 삭제했습니다. 대회 규정 걱정이 사라졌습니다.
  • 기회 음성 비서 Gleo에 앱 기능을 등록할 수 있습니다. "아이가 멀미해"라고 말하면 멀미 완화 모드가 켜지는 연동이 가능합니다. 기술 활용성 점수에 직접 기여합니다.
  • 제약 운전 중 시선을 끄는 애니메이션은 금지입니다. 운전자가 볼 수 있는 화면에 움직이는 광학 흐름을 띄우는 M1 원안은 규정과 충돌합니다.
  • 제약 주행 중 CPU는 5% 미만, 메모리는 400 MB 이하(내비가 아닌 앱 기준)입니다. 60 fps 연속 렌더링은 이 예산을 넘습니다.
  • 제약 DO(주행 중 사용) 선언이 없으면 앱이 주행 중 아예 실행되지 않습니다. 선언하더라도 CarUxRestrictions를 받아 기능별 제한을 직접 적용해야 합니다.

제약

설계에 반드시 반영할 규칙

필수

운전 중 애니메이션 금지

UI Design Guide · 주행 안전 설계

"운전 중 동영상, 애니메이션 이미지, 텍스트 자동 스크롤로 운전자 시선을 유도하면 안 된다"는 기본 원칙입니다. 정보는 1~2초 안에 파악할 수 있어야 합니다.

앱 설계: 운전석에서 보이는 화면에는 주행 중 정적인 방향 표시와 짧은 상태만 둡니다. 움직이는 큐는 조수석 창(Connect-W)이나 앰비언트 조명으로 보냅니다.

필수

성능 예산: 주행 중 CPU 5% 미만, RAM 400 MB 이하

성능 및 리소스 설계 · 심사 기준

내비가 아닌 앱의 주행 중 기준입니다. 정차 중에는 25% 이하. 터치 응답 0.25초, 앱 실행 10초, 버튼 반응 2초 이내도 심사 항목입니다.

앱 설계: 계속 그리는 화면 대신 이벤트가 있을 때만 그립니다. 신호 처리는 10~20 Hz로 충분하고, 큐 애니메이션은 짧게 끝냅니다.

필수

DO 선언 + CarUxRestrictions 연동

주행 규제 정책 · 개발 가이드

DO 미선언 앱은 주행 중 사용할 수 없습니다. 선언한 앱도 CarUxRestrictionsManager로 제한 상태를 받아 적용해야 합니다. 한국 기준 주행 중에는 차량·시트 설정 화면(NO_SETUP), 동영상, 긴 텍스트가 잠깁니다.

앱 설계: 탑승자 프로필·민감도 설정은 정차 중에만 열고, 주행 중에는 잠금 안내를 표시합니다. 테스트는 adb 주행 규제 명령으로 켜고 끕니다.

권장

하드웨어는 플랫폼 API로만

하드웨어 접근 정책

차량 센서에 직접 접근하지 말고 플랫폼 API를 쓰라고 하며, 자이로 등 일부 Android 센서는 차량에서 제한될 수 있다고 명시합니다.

앱 설계: 핵심 신호는 조향각·차속·내비 TBT로 잡고, 가속도계는 있으면 쓰는 선택 입력으로 둡니다.

권장

화면은 세로(1칸)와 가로(2칸) 둘 다

앱 구조 및 동작 모델 · Window Policy

앱 영역은 1~2개 창으로 나뉘고, 지정하지 않으면 세로 1칸으로 실행됩니다. 창 크기가 바뀌어도 핵심 기능이 보여야 하고, 백그라운드에서 돌아오면 마지막 상태를 복원해야 합니다.

앱 설계: 세로 화면은 상태와 다음 예고 하나, 가로 화면은 여기에 주행 리포트를 추가합니다.

권장

음성 출력은 오디오 포커스와 선행 묵음

오디오 포커스 · TTS 선행 묵음 가이드

모든 소리는 재생 전 포커스를 요청해야 하고, 음악과 동시에 나오려면 AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK을 씁니다. 음성 안내 앞에는 150~200 ms 묵음을 넣습니다. 시동이 꺼지면(Suspend) 포커스를 반납합니다.

권한과 개인정보

심사 가이드 · 보안 가이드

Vehicle SDK 권한, 특히 CONTROL_CAR_* 쓰기 권한은 App Market과 사전 협의·승인된 것만 선언할 수 있습니다. 주행 데이터를 차량 밖으로 보낼 때는 익명화하고 마케팅에 쓰지 않아야 하며, 위치를 쓰면 위치정보 이용약관을 제출해야 합니다.

앱 설계: 모든 처리를 차량 안에서 끝내는 기획서의 온디바이스 원칙은 심사 측면에서도 유리합니다. 필요한 권한 목록과 사유를 기획서에 표로 적습니다.

참고

우리 앱과 무관하지만 알아둘 것

  • 미디어 앱(동영상·게임·브라우저)은 주행 중 실행 자체가 금지됩니다. Steady Ride에 영상 콘텐츠를 넣으면 이 분류에 걸립니다.
  • App Market은 자동 업데이트가 없어 앱이 직접 버전 확인과 업데이트 안내(market://detail?package=…)를 구현해야 하고, 심사 요청마다 버전을 올려야 합니다.
  • 등록 자료: 아이콘 512×512, 스크린샷 2장 이상(2560×1380 등), 앱 이름 30자 이하, APK 600 MB 미만, IARC 연령 등급.
  • Playground 주소가 developers.pleos.ai로 바뀌었고, 에뮬레이터 2.1.0부터 CRN 입력과 LLM SDK가 없어졌습니다.
  • Connect Mobile 문서는 42dot 사내망 전용 콘솔과 스마트폰 앱 사용법이라 이번 대회와는 관련이 없습니다.
